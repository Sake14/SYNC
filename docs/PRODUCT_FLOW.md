# Пользовательский сценарий SYNC

## Вместе за несколько действий

Нажмите «Создать комнату» на главной: сразу открывается комната с ролью HOST.
Используется сохранённое имя или «Гость», название — «Вечер вместе»; отдельная форма
позволяет изменить эти значения при создании. Выберите трек, скопируйте приглашение
или покажите QR. Друг входит по ссылке и указывает имя. В комнате видны участники,
ведущий, подключение, готовность каждого, текущий трек и состояние синхронизации.

Каждый один раз нажимает «Включить звук / Готов слушать» в текущей вкладке. Успешный
unmuted `audio.play()`, продвижение native currentTime, буфер и калибровка часов подтверждают
готовность плеера; это не измерение физического звука. HOST нажимает Play после ready всех.
Pause доступна любому участнику, Play/Seek/выбор трека — HOST. Все команды используют
серверную timeline. HOST может передать роль другому участнику или исключить слушателя;
исключённый теряет доступ к комнате и её приватным файлам. Реакции ❤️ 🔥 😭 🎧 видят все подключённые
участники, включая отправителя. При потере связи аудио останавливается; reconnect
получает актуальный snapshot и снова подтверждает готовность. Ошибки не скрываются.

## Своя музыка и очередь

В «Ваша музыка» выберите собственный MP3/WAV/OGG/M4A, при желании задайте название
и нажмите «Загрузить в комнату». UI показывает прогресс фактической передачи и отдельный
этап проверки файла; «Отменить» прекращает запрос. Успех добавляет композицию в библиотеку
всех участников. Любой слушатель загружает и предлагает музыку кнопкой «+».
HOST выбирает трек, меняет порядок очереди и нажимает «Следующий трек».
Удалять запись может её автор или HOST. Максимум 50 записей; повтор одного трека допустим.
При окончании сервер выбирает следующий трек; новый файл автоматически проверяет буфер
и часы на уже активированном audio элементе, затем HOST запускает Play. Повторный Ready
при обычном окончании и смене композиции не нужен. Reload или реальный запрет autoplay
требуют нового пользовательского жеста.

Если общая шкала движется, но звук не слышен, раскройте «Звук не слышно?» и нажмите
«Восстановить звук»: это повторный запуск только локального audio элемента, без PLAY/SEEK
для других участников. Строка «Аудио: …» показывает native паузу, позицию, mute, громкость,
буфер и доступное состояние AudioSession. Она не подтверждает слышимость из динамиков.

Дефолтные ограничения: файл 20 МиБ, комната 100 МиБ/20 файлов, сервер 512 МиБ,
четыре одновременные загрузки, запись до четырёх часов. Квоты задаются в `.env.example`.
Парсер ограничивает фактические байты. Клиентский MIME и расширение не являются доказательством:
сервер проверяет signature и аудиометаданные, для WAV также RIFF length.
Нечитаемые файлы и видео отклоняются. Это проверка формата, а не антивирусный сканер.
Имена/пути назначает сервер. Загруженные файлы не попадают в Git или публичный каталог.

HTTP GET/HEAD/Range доступен только активным участникам данной комнаты, токен отсутствует
в URL/QR. Браузер получает HttpOnly медиа-cookie после проверки membership. Данные комнаты
живут в Map; после рестарта комнаты исчезают. Удаление комнаты по TTL очищает её файлы
при следующем минутном sweep; остатки прежнего процесса удаляются после 24 часов.
Приватные аудиофайлы для долговременного сохранения храните также у себя.

## Автоматический обязательный сценарий

`tests/e2e/product.spec.ts`, desktop/mobile Chromium:

1. A создаёт комнату одним кликом и выбирает Orbit; получает ссылку и QR.
2. Б открывает именно эту ссылку, входит; у обоих два участника.
3. Оба разрешают звук; сервер показывает ready 2/2.
4. A нажимает Play; проверяются настоящие `paused`, `currentTime` обоих HTMLAudioElement.
5. A перематывает и ставит Pause; Б получает позицию и останавливается.
6. Б отправляет 🔥; реакция и имя отображаются у обоих.
7. Б загружает оригинальный тестовый WAV; A видит его, оба работают с общей очередью.
8. HOST выбирает загрузку из очереди; оба получают одинаковые HTTP Range байты,
   включают и воспроизводят настоящий файл. Анонимный HTTP запрос получает 401.
9. Проверяются отсутствие ошибок страницы и горизонтального скролла.

Отдельный E2E проверяет поддельную музыку, превышение размера и успешный retry.
Vitest проверяет серверные права, stale revision, квоты, повреждённый WAV,
межкомнатную изоляцию, реакции, очередь, disconnect/reconnect и очистку файлов.
Более ранние тесты дополнительно проверяют NTP, задержки сообщений, autoplay denial,
смену трека, HOST transfer и реальные currentTime/playbackRate.

## Вручную на двух физических устройствах

Эти проверки ещё нужно выполнить; результаты браузерной автоматизации их не заменяют.
Используйте два устройства, доступный обоим origin (не localhost) и свои записи.
Для LAN добавьте origin в CLIENT_ORIGINS; HTTPS frontend должен использовать HTTPS Socket.IO.

- A создаёт комнату; Б входит по QR с камеры телефона. Проверьте копирование ссылки,
  сканирование QR, имя HOST, список участников и готовность на обоих экранах.
- До активации на Б Play должен быть недоступен. Разрешите звук на обоих, запустите,
  перемотайте и поставьте паузу. Подтвердите слышимое воспроизведение одной композиции.
- Откройте `/sync-lab`, запишите offset/RTT и ошибку временной позиции. Для оценки реальной
  акустической задержки отдельно запишите импульсы обоих динамиков одним микрофоном;
  drift UI не измеряет задержку динамиков, Bluetooth или аудиодрайвера.
- Повторите с разными сетями, мобильным интернетом, слабым Wi-Fi, Bluetooth-наушниками.
  Зафиксируйте устройства/ОС/браузер/сеть; не переносите результат одной пары на все пары.
- Заблокируйте экран Б и переведите браузер в фон, затем вернитесь. Проверьте догон
  актуальной позиции и сообщение о необходимости повторного включения звука, если ОС его требует.
- Отключите сеть Б, смените трек на A, восстановите сеть. Проверьте свежий snapshot,
  приватную библиотеку и необходимость готовности нового файла. Отключите HOST: роль должна перейти Б.
- Б отправляет каждую из четырёх реакций; обе вкладки показывают один экземпляр.
  Добавьте треки с обоих устройств, измените порядок, удалите свою запись и выберите следующую.
- Загрузите собственные WAV и MP3 (при наличии также OGG/M4A), включая кириллическое имя.
  Проверьте воспроизведение и перемотку на обоих. Safari/iOS может не декодировать отдельные
  кодеки: ошибка должна оставаться видимой и устройство не должно считаться ready.
- Проверьте слишком большой файл, неверный формат, отмену и потерю сети во время загрузки,
  понятную ошибку и успешную повторную загрузку. После выхода проверьте отказ HTTP доступа.
